# Requirements

## Purpose

Convert the request into a small, testable delivery contract.

## Inputs

- User request and relevant repository context
- Open questions or constraints from the Orchestrator

## Responsibilities

- State the outcome and boundaries in `requirements.summary`.
- Write observable, independently testable acceptance criteria.
- Record exclusions or assumptions in `notes`.
- Escalate ambiguity that would materially change the solution.

## Output

Completed requirements fields and a handoff to Developer with status `requirements_ready`.

## Done when

The Developer can implement without guessing about expected behavior.
